# План и статус: Telegram-бот персональных детских сказок (harness + skills)

## 1. Цель и границы

Бот для родителей: по профилю ребёнка (имя, пол, возраст, интересы) выбирает формат и сочиняет сказку на русском — простую, понятную, безопасную. Начиная со второй итерации бот устроен как **агентный харнесс**: навыки-методики, инструменты, guardrails, память, трассировка.

**В MVP:** профили, 14 форматов, сказка на ночь, «Для родителей», история и оценки, дневной лимит, удаление данных, админ-статистика.
**Вне MVP:** оплата, озвучка, иллюстрации, Mini App, интерактивные сказки «выбери путь», мультиязычность (см. дорожную карту).

## 2. Технологический стек

| Область | Решение | Почему |
|---|---|---|
| Язык / менеджер | Python 3.14, uv | воспроизводимые окружения, `uv.lock` |
| Telegram | aiogram 3.31 (Bot API 10.x) | async, FSM, CallbackData, `sendMessageDraft` |

| FSM | память процесса / Redis | рестарт не теряет анкету |
| Конфиг/логи | pydantic-settings, structlog | типизированные настройки, JSON-логи без ПДн |
| Качество | ruff, mypy `--strict`, pytest, eval-прогон, GitHub Actions | |
| Доставка | Docker, docker-compose, devcontainer | |

## 5. Что проверено, а что нет

**Проверено автоматически (296 тестов, ruff, mypy `--strict`):**
- агентный цикл на сценарной «модели»: явный навык (один ход, без инструментов), авто-режим с `load_skill`, ошибки инструментов, границы шагов, прогресс по ходам, наложение «на ночь», объём с множителями, память о прошлых сказках;
- guard-слой: экран входа (кризис/инъекции/чувствительное), проверки текста, критик (в т. ч. мусорный JSON и сбой), правка, блокировка, повторная правка не зацикливается;
- загрузчик навыков: все встроенные проходят валидацию, кривые отвергаются, перекрытие через `SKILLS_DIR`, защита от path traversal;
- адаптер Anthropic на подставном HTTP-транспорте с SSE: стриминг дельт, сборка `tool_use`, usage с кэшем, отказ, ошибки API, форма запроса;
- Луна и тёплые слова: валидность `soul.md` и женский голос во всех UI-строках; правила базы знаний (обращение на «вы» без указания пола, без ролевых слов, имя ребёнка только в именительном падеже); выбор слов по настроению, времени суток и истории; расписание (окно, личный час, интервалы); атомарный захват слота (две реплики не дублируют рассылку); блокировка бота, flood control; приглашение показывается один раз;
- сквозные сценарии бота с настоящими хендлерами; eval-прогон **каждый формат × 3 профиля** (в т. ч. с «на ночь»); миграции вверх/вниз и соответствие моделям; SQL для PostgreSQL (offline); вебхук с секретом; wheel содержит навыки.

**Не проверялось — сделайте при первом запуске:**
1. **Качество текста на реальной модели.** Это главное. Запустите `make eval` с ключом и прочитайте несколько сказок по каждому формату для разных возрастов: склонение имён, соблюдение объёма, ритм стихов, точность фактов в познавательных, тон метафорических. Методики — в `src/skazki_bot/skills/*/SKILL.md`, правятся без кода.
2. **Реальный Anthropic API**: названия моделей (`LLM_MODEL`, `GUARD_MODEL`), поведение tool use вживую, срабатывание prompt caching (системный промпт ~6,5 тыс. символов — сверьте порог кэширования модели по `cache_read` в `/stats`/логах).
3. **Эвристики guard-слоя**: регулярные выражения для кризисных и «чувствительных» тем, жестокости и смерти — это первая линия, а не гарантия. Смотрите на ложные срабатывания в `generation_runs.issues`.
4. **Критик**: насколько строго он оценивает и как часто просит правку (`/stats` → «правок») — подстройте промпт в `harness/prompts.py` или отключите.
5. Реальный Telegram (`sendMessageDraft`), PostgreSQL/Redis вживую, `docker build`, GitHub Actions (версии actions в `ci.yml`).
6. **Тон и грамматика тёплых слов** — прочитайте `knowledge/cheer/*.yaml` глазами носителя языка; автоматические проверки ловят типичные ошибки, но не вкус. Живая доставка планировщика в Telegram и поведение часового пояса.

## 6. Риски и меры

| Риск | Мера |
|---|---|
| Метафорические сказки на тяжёлые темы | входной экран; режим бережности (`<safety_note>`); справочник тяжёлых тем; «Для родителей» с рекомендацией психолога; кризис — отказ с контактами |
| Расходы | дневной лимит; дешёвая модель-критик; явный формат — один ход без инструментов; `max_tokens` по объёму; трассы токенов в БД |
| Качество на разных возрастах | возрастные профили, множители длины, критик, eval-прогон |
| Prompt injection | очистка ввода, теги-данные, явное правило в системном промпте, входной экран |
| Персональные данные детей | минимизация, в трассах и логах нет текстов/имён, раскрытие передачи данных LLM в «Приватности», `/delete` |
| Недоступность LLM | ретраи SDK, общий таймаут, понятные сообщения, квота не списывается |
| Несколько реплик бота | блокировка двойного запуска пока в памяти процесса — перенести в Redis; рассылка тёплых слов защищена от дублей атомарным захватом слота в БД |
| Навязчивость проактивных сообщений | только по согласию (по умолчанию выкл.), окно 10–21, личный час, минимальные интервалы, кнопка «Не присылать» под каждым сообщением, блокировка бота отключает рассылку |

## 7. Дорожная карта

1. **Интерактивные сказки «выбери путь»**: сегменты с кнопками выбора, состояние в БД/FSM.
2. **Серии**: компаньоны и «мир» ребёнка как постоянный контекст (расширение `sequel`), календарь тем.
3. **Модерация и жалобы**: кнопка «пожаловаться», выборочная проверка трасс, тонкая настройка порогов guard-слоя.
4. **Монетизация**: Telegram Stars, повышенный лимит.
5. **Озвучка** (TTS) для «релакса» и «на ночь»; **иллюстрации**; PDF/EPUB-книжка.
6. **Mini App** для профиля и библиотеки; напоминание «пора на сказку».
7. **Аналитика** без ПДн: удержание, оценки форматов, стоимость сказки по навыкам.
8. **Мультиязычность**: i18n текстов, навыки на других языках.
9. Блокировки/очереди и кэш навыков в Redis, метрики Prometheus, Sentry.
10. **Луна, следующие шаги**: личный часовой пояс для тёплых слов; режим «подстройки» через LLM (по методике `cheer/SKILL.md`, с теми же проверками guard-слоя); расширение баз знаний (больше сюжетов, фольклорных заготовок и слов); напоминание «пора на сказку» по желанию.
