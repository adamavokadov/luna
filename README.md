# 🌙 skazki-bot — персональные сказки для детей в Telegram

Telegram-бот, который сочиняет сказки на русском языке **для конкретного ребёнка**. Родитель указывает имя, пол, возраст и интересы — а дальше работает **агентный харнесс**: он выбирает формат (из 14 навыков-методик), пишет сказку со стримингом в чат, проверяет её guard-слоем и критиком, исправляет по замечаниям и записывает трассу запуска.

## Что умеет

**14 форматов (навыков):** 🌙 сказка на ночь · 🦋 метафорическая (помогает прожить трудную ситуацию) · 🎒 подготовка к событию (садик, врач, школа…) · 🧘 сказка-релакс · 🎵 в стихах · 🔁 цепочка (как «Репка») · 🧩 с загадками · 😄 смешная · 🔬 познавательная · 💛 о добре и ценностях · 🎂 праздничная · 🔗 продолжение любимой · ✨ авторская волшебная · 📖 классика по-новому (18 сюжетов).

- **Режимы:** «Удиви меня» (формат выбирает модель), «Выбрать формат», «Классика по-новому», «Своя идея». Для метафорических сказок и подготовки к событию есть **быстрые темы** («Боится темноты», «Идём в садик»…).
- **«Для родителей»**: где нужно, к сказке прилагается отдельная заметка — как продолжить разговор, ответы на загадки, факты и безопасный опыт.
- **Профиль ребёнка**: имя, пол (для правильных окончаний), возраст 2–10, интересы, заметка; до 3 профилей.
- **Живой стриминг** через `sendMessageDraft` с откатом на «печатает…».
- **Память**: помнит оценки 👍/👎 и недавние сказки — не повторяется, умеет продолжать.
- История сказок, длина, дневной лимит, **удаление всех данных** (`/delete`), админ-команда `/stats`.

## Как устроен харнесс

```
Родитель ─► handlers (aiogram, FSM) ─► TaleService: лимиты, память, сохранение, трассы
                                            │
                                            ▼
                                       TaleHarness
  ┌──────────────────────────────────────────────────────────────────────────────────┐
  │ 1. Входной guard: кризис → поддержка, инъекции → отказ, чувствительное → бережно │
  │ 2. Навыки: явный выбор → тело в контексте;  авто → модель зовёт load_skill        │
  │ 3. Цикл «модель ↔ инструменты» (≤ N шагов; стрим каждого хода в sendMessageDraft) │
  │ 4. Выходной guard: проверки + LLM-критик (дешёвая модель) → одна правка → блок    │
  │ 5. Трасса: шаги, инструменты, токены, кэш, время, замечания → generation_runs     │
  └──────────────────────────────────────────────────────────────────────────────────┘
        инструменты: load_skill · read_skill_file · pick_classic · get_recent_tales
```

- **Навыки по спецификации Agent Skills** (`name`/`description`/`metadata`, `references/`) с прогрессивным раскрытием: каталог всегда в промпте (~6,5 тыс. символов на 14 навыков), тело — по требованию, справочники — по запросу. Подробности и авторинг: [`docs/SKILLS.md`](docs/SKILLS.md).
- **Принцип наименьших привилегий**: при явном выборе формата модель не получает лишних инструментов — обычно один ход.
- **Guardrails слоями**: детерминированный входной экран → системные правила безопасности → детерминированные проверки текста (язык, объём, имя ребёнка, жестокость, «утечки» промпта) → LLM-критик → одна правка → блокировка. Тема вроде «папа бьёт маму» не доходит до модели: бот отвечает поддержкой (112 и детский телефон доверия 8-800-2000-122 — для России).
- **Наблюдаемость**: каждый запуск пишет в `generation_runs` метрики и коды замечаний (без текстов и имён); `/stats` у админа показывает форматы, время, токены и долю правок за неделю.
- **Надёжность**: общий таймаут, ретраи SDK, квота списывается только за успешную сказку, защита от двойного запуска, события одного пользователя обрабатываются по очереди.

Стоимость одной сказки: явный формат = 1 вызов основной модели + 1 короткий вызов критика (дешёвая модель); «Удиви меня» = 2 + критик; правка добавляет вызов. Критика можно отключить (`CRITIC_ENABLED=false`).

## Быстрый старт в GitHub Codespaces

1. Распакуйте архив **в корень репозитория**, сделайте commit и push.
2. Репозиторий → **Code → Codespaces → Create codespace**. `postCreateCommand` поставит зависимости, создаст `.env` и применит миграции.
3. Секреты (**Settings → Secrets and variables → Codespaces**): `BOT_TOKEN` (от [@BotFather](https://t.me/BotFather)) и `ANTHROPIC_API_KEY`. Без ключа: в `.env` поставьте `LLM_PROVIDER=fake` — заглушка тоже маршрутизирует навыки и вызывает инструменты.
4. Запуск:

   ```bash
   make run          # миграции + бот (polling)
   make check        # ruff + mypy + pytest + проверка навыков — то же, что гоняет CI
   make eval         # каждый формат × 3 профиля: объём, шаги, замечания, токены, время
   ```

> Codespace засыпает после простоя, и бот вместе с ним. Для работы 24/7 разверните бота на хостинге (см. ниже).

## Конфигурация

Полный список с комментариями — в [`.env.example`](.env.example). Ключевые:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота |
| `LLM_PROVIDER` | `anthropic` | `anthropic` или `fake` |
| `ANTHROPIC_API_KEY` | — | ключ Anthropic |
| `LLM_MODEL` | `claude-sonnet-5-5` | основная модель |
| `GUARD_MODEL` | `claude-haiku-5-5` | дешёвая модель-критик |
| `CRITIC_ENABLED` | `true` | LLM-проверка готовой сказки |
| `HARNESS_MAX_STEPS` / `_MAX_REVISIONS` / `_TIMEOUT_S` | `4` / `1` / `180` | границы агентного цикла |
| `SKILLS_DIR` | — | свои навыки (перекрывают встроенные) |
| `DAILY_TALE_LIMIT` | `5` | сказок в сутки на родителя |
| `DATABASE_URL` | SQLite в `./data` | `postgresql+asyncpg://…` для прода |
| `REDIS_URL` | — | FSM-состояния в Redis |
| `RUN_MODE` | `polling` | `webhook` для продакшена |
| `ADMIN_IDS` | — | Telegram-id без лимитов и с `/stats` |

## Структура проекта

```
src/skazki_bot/
  harness/   runner.py (цикл) · skills.py (загрузчик) · tools.py · guard.py · prompts.py · types.py
  skills/    14 навыков: <имя>/SKILL.md [+ references/]
  llm/       base.py (ChatLLM) · anthropic_llm.py (стрим, tool use) · fake.py · parse.py · sanitize.py
  services/  tale_service.py (лимиты, память, трассы) · streaming.py (sendMessageDraft)
  stories/   18 классических сюжетов + подбор
  db/        модели, репозиторий, трассы запусков
  bot/       handlers/, keyboards, callbacks, texts, middlewares
  evals.py   прогон форматов на эталонных профилях
migrations/  Alembic (0001 базовая схема, 0002 навыки и трассы)   tests/  186 тестов
```

## Продакшен

```bash
cp .env.example .env           # BOT_TOKEN, ANTHROPIC_API_KEY, при желании RUN_MODE=webhook
docker compose up --build -d   # бот + PostgreSQL + Redis
```

Для webhook нужен HTTPS: `RUN_MODE=webhook`, `WEBHOOK_BASE_URL`, `WEBHOOK_SECRET`, порт `8080` (проверка живости — `GET /healthz`).

## Разработка

```bash
make fmt                              # форматирование и автоисправления
make revision m="что изменилось"      # миграция после правки моделей
make skills-check dir=./my-skills     # проверка своих навыков
```

CI гоняет ruff, mypy `--strict`, pytest, проверку навыков и сборку Docker-образа. Тест миграций падает, если модели изменили без миграции. Тесты адаптера Anthropic идут на подставном HTTP-транспорте с SSE-потоком в формате Messages API.

План, статус, что проверено и дорожная карта — в [`docs/PLAN.md`](docs/PLAN.md).
